# Hardware reference design and bench data still needed

**Legacy v2 document.** The latest supplied firmware and discovered working camera project supersede the GPIO/UART tables below. Use [SmartBin 0.3](SMARTBIN_HANDOFF.md) for the current wiring, firmware and category-first kiosk flow. The linked wiring sheets have been updated to that current map.

This replaces the earlier two-bin ESP32-only sketch. The proposed system uses your actual three-bin / ESP32-to-Nano arrangement. It is a reference for a classic NodeMCU-32S-style ESP32 with a bare parallel OV7670; preserve any camera wiring/capture firmware that is already proven on your board.

## Confirmed parts from the supplied lists

Combined list: three HC-SR04 modules; three SG90 180-degree servos; one MG996R listed as 360-degree (you confirmed continuous rotation); one Nano V3 ATmega328P-compatible board; an OV7670; HX711 amplifier; one 5 kg load-cell bar and plate; one 1k and one 2k resistor; breadboards/jumpers; four AA cells, holder and charger. ESP32 identification comes from your message and linked NodeMCU-32S reference, not the invoices.

A regulated, adequately sized servo supply is still needed for a dependable build. The reference bench supply target is regulated 5 V with 5 A capacity, subject to checking the actual servos' peak currents. Do not run four servos from the ESP32/Nano regulator or treat the 4xAA holder as a regulated supply. Add bulk decoupling near the servo branch, adequate power wires and a conveniently reachable servo-power disconnect.

### ESP32 connections

| Peripheral signal | ESP32 GPIO / rail |
| --- | --- |
| Nano RX D0 | GPIO16 TX2 |
| Nano TX D1 | 1k series resistor -> node -> GPIO17 RX2; 2k node-to-GND |
| HX711 DT/DOUT | GPIO32 |
| HX711 SCK/CLK | GPIO33 |
| HX711 VCC on single-supply module | 3V3; verify the breakout variant |
| OV7670 D0, D1, D2, D3 | GPIO34, GPIO35, GPIO36, GPIO39 |
| OV7670 D4, D5, D6, D7 | GPIO18, GPIO19, GPIO21, GPIO22 |
| OV7670 XCLK, PCLK | GPIO27, GPIO23 |
| OV7670 VSYNC, HREF | GPIO26, GPIO25 |
| OV7670 SIOD/SDA, SIOC/SCL | GPIO13, GPIO14 |
| OV7670 module VCC, GND | 3V3, GND |
| OV7670 RESET, PWDN | 3V3, GND, if those active-low-reset/power-down pins match your module |

GPIO34–39 are input-only on the original ESP32, so the plan uses them only for camera data inputs. It avoids flash GPIO6–11 and strapping pins in this reference map. Keep parallel-camera wires short. Check whether the camera module already includes SCCB pull-ups; do not assume every OV7670 breakout is identical. A FIFO camera variant needs a different capture adapter.

### Nano connections

| Signal | Nano pin |
| --- | --- |
| UART RX / TX | D0 / D1 |
| Food SG90 / recycle SG90 / reject SG90 | D3 / D5 / D6 |
| Continuous pusher MG996R signal | D9 |
| Food HC-SR04 TRIG / ECHO | D4 / D8 |
| Recycle HC-SR04 TRIG / ECHO | D7 / D11 |
| Reject HC-SR04 TRIG / ECHO | D10 / D12 |
| HC-SR04 VCC / GND | Nano 5V logic rail / common GND |

Putting the 5 V sonar modules on the Nano avoids three additional ESP32 echo dividers. Use the included 1k/2k pair for Nano TX -> ESP32 RX: nominal 5 V becomes 3.33 V. ESP32 TX can feed the classic ATmega328P RX input directly; confirm your board is the classic 5 V Nano, not a different Nano-family module.

Run the ESP32 from USB. Feed the Nano 5V pin and sonars through a regulated 5 V **logic branch**. Feed all servo V+ wires through a separate high-current branch. These two branches may originate at the same adequate regulated supply, but servo current must bypass board regulators and thin breadboard power routes. Join all grounds, including ESP32 USB ground, at a common reference. Do not join the external positive rail to the ESP32 USB 5 V line. Disconnect external Nano power and ESP32 UART wires for Nano USB programming, then restore the run wiring. Some CH340 clones require RX isolation from the USB-serial transmitter; verify your clone if UART contention occurs.

## Proposed mechanism without end switches

Use a circular inspection tray with three separately gated outlets around its perimeter, each leading to a different bin. A continuous rotary paddle sweeps in one direction; only the destination gate opens. This matches a 360-degree continuous servo without requiring a return-to-home angle. It is **not** a linear pusher that must be reversed to an unknown home position.

The load cell supports the inspection tray. Mount one end of the load-cell bar to a rigid base and the plate to the intended moving end, following its mounting direction. Keep the plate clear of surrounding walls/door frames so they cannot share its weight. The pusher motor support is fixed to the enclosure, not part of the load measurement. Moving contact can disturb readings; empty detection uses a stable window and a maximum run timeout.

Before movement, weigh and classify with the paddle stopped. During the sweep, wait until the plate is stably empty; command motor neutral, then door closed. No HX711 reading tells you the paddle's angle or confirms which chute received the item. There are no door-position/arrival sensors in your parts list. The design records controller commands and an empty tray as the completion evidence, not physical door feedback. Keep the rotating parts enclosed; do not make the computer-vision hand detector the only physical guard.

## Firmware and calibration

1. `hx711_calibration/hx711_calibration.ino`: flash to the ESP32 with an empty plate, send `TARE` via USB serial, then place a known mass and send its mass in grams. It prints the signed scale factor and saves the empty-plate offset in NVS. Verify with a second known mass.
2. `esp32_gateway/config.h`: set Wi-Fi/API/device key, your verified camera pin map and frame byte order, and the measured HX711 factor. Set `HARDWARE_CONFIGURED=true` only after wiring/calibration are checked.
3. `nano_controller/config.h`: bench-adjust each SG90 closed/open pulse and the continuous servo's actual neutral/forward pulses. Continuous servo pulses specify speed/direction, **not angle**. Set local fullness cutoffs from measured bin geometry and enable the configured guard.
4. Apply the same geometry to the backend using `station.example.json` and `configure_station.py`. Default numbers are placeholders, not measurements of your enclosure.
5. Flash Nano and gateway, power the servo branch last, and test one destination at a time. Calibration/bench operation is still required even when a sketch compiles.

The gateway samples HX711 and keeps the UART heartbeat running in an independent FreeRTOS task. A long model request cannot starve the Nano watchdog. It persists unresolved cycles before actuation and never automatically repeats a push after a reboot. The retired `esp32_bin_controller` sketch deliberately refuses compilation to prevent accidentally using the old two-bin wiring.
